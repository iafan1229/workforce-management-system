# Workforce 수동 배정 및 날짜 중심 운영 보강 설계

## 1. 목적

이 문서는 기존 `Workforce 데이터 파이프라인 MVP` 설계에 `수동 배정`과 `날짜 중심 운영 흐름`을 보강하기 위한 추가 설계를 정의한다.

기존 MVP는 `출근 등록`, `엑셀 업로드`, `인력 조회`, `배정 이력 축적`이라는 데이터 파이프라인을 만드는 데 집중했다. 하지만 실제 운영에서는 다음 요구가 추가되었다.

- 엑셀 업로드 전에도 관리자가 직접 배정할 수 있어야 한다.
- 날짜가 운영의 기준이므로, 화면 전체가 선택한 날짜 컨텍스트 아래에서 움직여야 한다.
- 인력 조회 화면에서도 선택한 날짜 기준으로 출근과 배정 상태를 보고 운영 화면으로 돌아갈 수 있어야 한다.

이번 보강 설계의 목표는 이 요구를 기존 구조를 크게 깨지 않는 선에서 흡수해, 이후 `반자동 추천 배정` 기능이 올라갈 수 있는 안정적인 운영 기반을 만드는 것이다.

## 2. 변경 배경

기존 설계는 `오늘 운영 화면`과 `오늘 출근 등록 화면`을 중심으로 잡혀 있었다. 이 구조는 당일 운영만 보면 단순하지만, 실제 현장처럼 `2026-05-24`, `2026-05-25` 등 날짜별로 출근과 배정을 관리해야 할 때 한계가 있다.

특히 다음 문제가 생긴다.

- 날짜를 바꾸면 화면 의미가 달라지는데 라우팅은 여전히 `오늘` 중심이다.
- 수동 배정을 넣으려면 출근 등록 화면이 실제 운영 허브가 되어야 하는데, `오늘`이라는 표현이 과도하게 좁다.
- 인력 조회에서 특정 날짜 기준 액션을 안내하려면 전체 앱이 공통 날짜 컨텍스트를 알아야 한다.

따라서 이번 보강에서는 `날짜를 먼저 선택하고, 그 날짜 안에서 운영한다`는 구조로 흐름을 재정의한다.

## 3. 목표

이 보강 이후 인증된 관리자는 다음을 수행할 수 있어야 한다.

- 로그인 후 달력에서 운영 날짜를 선택한다.
- 선택한 날짜 기준으로 출근자를 등록한다.
- 선택한 날짜 기준으로 출근자에게 수동 배정을 생성, 수정, 해제한다.
- 출근은 했지만 아직 배정되지 않은 상태를 허용한다.
- 같은 날짜의 배정이 엑셀 업로드로 들어오면 최종값을 엑셀이 덮어쓴다.
- 인력 조회 화면과 인력 상세 화면에서 선택 날짜 기준 운영 상태를 확인하고, 적절한 액션으로 운영 화면에 진입한다.

## 4. 비목표

이번 보강에도 아래 기능은 포함하지 않는다.

- 자동 배정 확정
- 추천 점수 계산
- 파트별 목표 인원 기반 실시간 부족 인원 대시보드
- 다중 날짜 일괄 수정
- 과거 배정 이력 전체 편집
- 작업자용 모바일 UI

## 5. 확정된 핵심 결정

브레인스토밍을 통해 아래 결정을 확정했다.

- 수동 배정은 `출근 등록 화면`에서 바로 수행한다.
- 수동 배정은 `선택한 날짜` 기준으로만 생성, 수정, 해제한다.
- 배정이 없는 상태를 허용한다.
- 수동 배정은 즉시 `worker_skills` 누적 경험에 반영한다.
- 같은 날짜에 엑셀 업로드가 들어오면 엑셀이 기존 수동 배정을 덮어쓴다.
- `workers`, `workers/[workerId]`에서는 직접 저장하지 않고 상태 기반 액션 버튼으로 운영 화면에 진입시킨다.
- 로그인 후 첫 화면은 `달력 기반 날짜 선택 화면`으로 바꾼다.
- 날짜별 운영 화면의 상단 왼쪽에는 `날짜 변경` 버튼을 둔다.

## 6. 라우팅 및 화면 구조

### 6.1 날짜 선택 진입 화면

로그인 후 첫 진입 화면은 날짜 선택 전용 화면이다.

- 경로: `/`
- 주요 UI: 월간 달력
- 기본 포커스: 오늘 날짜
- 동작: 날짜 클릭 시 `/operations/[workDate]`로 이동

이 화면은 운영 정보를 과하게 보여주지 않는다. 목적은 오직 `어떤 날짜를 운영할지 선택`하는 것이다.

### 6.2 날짜별 운영 대시보드

- 경로: `/operations/[workDate]`
- 목적: 선택한 날짜의 운영 허브
- 상단 왼쪽: `날짜 변경` 버튼
- 주요 링크:
  - 출근/배정 관리
  - 배정표 업로드
  - 인력 조회

초기 버전의 `날짜 변경` 버튼은 작은 팝오버 달력 없이, 날짜 선택 화면(`/`)로 돌아가는 단순 링크여도 충분하다.

### 6.3 날짜별 출근 및 수동 배정 화면

- 경로: `/operations/[workDate]/attendance`
- 역할: 선택 날짜의 출근 등록과 수동 배정 허브

화면 구성:

- 상단: 선택 날짜 표시
- 왼쪽 패널: 출근 등록 폼
- 오른쪽 패널: 해당 날짜 출근자 목록

출근자 목록 각 행에는 다음이 포함된다.

- 이름
- 전화번호
- 현재 배정 상태: `미배정` 또는 카테고리명
- 업무 카테고리 드롭다운
- 상태 기반 액션 버튼:
  - 배정이 없으면 `배정하기`
  - 배정이 있으면 `수정`
- 배정이 있을 때만 `배정 해제`

### 6.4 날짜별 업로드 화면

- 경로: `/operations/[workDate]/upload`
- 역할: 선택 날짜의 배정 엑셀 업로드

기존 업로드 규칙은 유지하되, `workDate`는 URL과 화면 컨텍스트 기준으로 맞춘다. 관리자가 업로드 화면에서 다른 날짜를 임의로 고르는 대신, 현재 선택된 날짜에 업로드하도록 흐름을 단순화한다.

### 6.5 날짜별 인력 조회 화면

- 경로: `/operations/[workDate]/workers`
- 역할: 선택 날짜 기준 인력 검색 및 운영 진입

검색 결과 카드에는 선택 날짜 기준 상태를 반영한 액션 버튼을 보여준다.

- 선택 날짜 출근 안 함: `출근 등록하러 가기`
- 선택 날짜 출근함 + 배정 없음: `배정하기`
- 선택 날짜 출근함 + 배정 있음: `배정 수정`

버튼은 모두 `/operations/[workDate]/attendance`로 이동하며, `focusWorkerId` 같은 쿼리 파라미터로 대상 인력을 바로 찾거나 강조한다.

### 6.6 날짜별 인력 상세 화면

- 경로: `/operations/[workDate]/workers/[workerId]`
- 역할: 선택 날짜 기준 운영 상태 + 누적 이력 확인

상세 화면은 기존 프로필, 최근 배정, 숙련 업무를 유지하되, 상단 액션은 선택 날짜 기준으로 동작한다.

- 선택 날짜 출근 안 함: 출근 등록 유도
- 선택 날짜 배정 없음: 배정하기 유도
- 선택 날짜 배정 있음: 배정 수정 유도

실제 저장은 여전히 `/operations/[workDate]/attendance`에서만 수행한다.

## 7. 데이터 모델과 상태 규칙

### 7.1 `attendances`

기존과 동일하게 날짜별 출근 기록을 저장한다.

- 고유 제약: `worker_id + work_date`
- 의미: 특정 인력이 특정 날짜에 운영 가능한 상태였음을 뜻한다.

### 7.2 `assignments`

기존과 동일하게 날짜별 배정 기록을 저장하되, `source` 사용 범위를 확장한다.

- `manual_assignment`: 운영 화면에서 수동으로 저장한 배정
- `excel_upload`: 업로드로 반영된 배정

핵심 제약:

- 한 사람은 같은 날짜에 하나의 배정만 가진다.
- 고유 제약은 계속 `worker_id + work_date`를 사용한다.

### 7.3 `worker_skills`

기존과 동일하게 인력별 업무 경험 누적치를 저장한다.

이번 보강에서 중요한 추가 규칙은 다음과 같다.

- 수동 배정 생성 시 해당 업무 `count + 1`
- 수동 배정 수정 시 기존 업무 `count - 1`, 새 업무 `count + 1`
- 배정 해제 시 기존 업무 `count - 1`
- 엑셀 덮어쓰기 시 수동 수정과 같은 방식으로 조정
- 감소 결과가 `0`이면 해당 행을 삭제
- 어떤 경우에도 음수가 되면 안 된다

## 8. 수동 배정 동작 규칙

### 8.1 배정 생성

조건:

- 선택 날짜에 해당 인력이 출근 등록되어 있어야 한다.
- 같은 날짜의 기존 배정이 없어야 한다.

동작:

1. `assignments`에 새 행 생성
2. `source = manual_assignment`
3. `worker_skills` 해당 업무 경험 `+1`

### 8.2 배정 수정

조건:

- 선택 날짜에 기존 배정이 있어야 한다.

동작:

1. 기존 배정 업무와 새 업무가 다르면 기존 업무 경험 `-1`
2. 새 업무 경험 `+1`
3. `assignments.task_type_id` 갱신
4. `source = manual_assignment`

같은 업무로 다시 저장하는 경우에는 경험 값 변화 없이 저장 성공만 처리해도 된다.

### 8.3 배정 해제

조건:

- 선택 날짜에 기존 배정이 있어야 한다.

동작:

1. 해당 날짜의 `assignment` 삭제
2. 기존 업무 경험 `-1`
3. 감소 후 `count = 0`이면 `worker_skills` 행 삭제

### 8.4 미배정 상태 허용

출근 등록과 배정은 분리한다.

- 출근만 먼저 등록 가능
- 나중에 배정 가능
- 이미 배정된 사람도 다시 `미배정` 상태로 되돌릴 수 있음

## 9. 엑셀 업로드와 수동 배정 충돌 규칙

이번 보강에서는 `엑셀이 수동 배정을 덮어쓴다`를 명시적 운영 규칙으로 채택한다.

해석:

- 같은 날짜의 수동 배정이 있더라도 업로드는 실패하지 않는다.
- 업로드가 들어온 시점의 엑셀 값이 해당 날짜 최종 배정값이 된다.

동작 규칙:

1. 기존 배정이 없으면 일반 업로드와 동일하게 생성
2. 기존 배정이 있고 업무가 다르면:
   - 기존 업무 경험 `-1`
   - 엑셀 업무 경험 `+1`
   - `assignment.task_type_id`를 엑셀 업무로 갱신
   - `source = excel_upload`
3. 기존 배정이 있고 업무가 같으면:
   - 경험 값 변화 없음
   - `source = excel_upload`로만 갱신

이후 관리자가 다시 수동으로 바꾸면, 그 시점의 수동 저장이 다시 최종값이 된다. 즉 같은 날짜 배정은 `마지막 저장 기준(last write wins)`으로 본다.

## 10. 조회 화면의 상태 기반 액션

조회 화면은 저장 화면이 아니라 운영 진입 화면 역할만 한다.

### 10.1 인력 조회 화면

검색 결과는 선택 날짜 기준으로 아래 3상태 중 하나를 가져야 한다.

- `not_attended`
- `attended_unassigned`
- `attended_assigned`

버튼은 상태에 따라 다르게 노출된다.

- `not_attended` -> `출근 등록하러 가기`
- `attended_unassigned` -> `배정하기`
- `attended_assigned` -> `배정 수정`

### 10.2 인력 상세 화면

상세 화면도 같은 상태 모델을 사용한다.

이렇게 하면 조회 화면과 운영 화면의 책임이 분리된다.

- 조회 화면: 상태 확인, 적절한 액션 안내
- 출근/배정 화면: 실제 저장

## 11. 에러 처리

주요 에러 처리 규칙은 다음과 같다.

- 잘못된 날짜 포맷이면 유효한 날짜 선택 화면으로 이동시킨다.
- 잘못된 `workerId`, `focusWorkerId`는 화면 전체를 깨지 말고 일반 목록으로 보여준다.
- 출근하지 않은 인력은 해당 날짜에 배정 저장을 허용하지 않는다.
- 존재하지 않는 `task_type`으로는 저장할 수 없다.
- 엑셀 업로드는 기존과 동일하게 한 줄이라도 검증 실패 시 전체 실패다.
- 경험 감소 과정에서 음수가 생기려 하면 서버에서 실패로 처리한다.

오류 메시지는 관리자 운영 도구 성격에 맞게 구체적으로 보여준다.

- `선택한 날짜에 출근 등록이 되어 있지 않습니다.`
- `해당 날짜의 기존 배정을 찾을 수 없습니다.`
- `업무 카테고리를 찾을 수 없습니다.`

## 12. 테스트 범위

### 12.1 도메인 테스트

- 날짜별 출근 등록 분리
- 수동 배정 생성
- 수동 배정 수정
- 수동 배정 해제
- 엑셀 업로드 덮어쓰기
- `worker_skills` 증가, 감소, 0일 때 삭제

### 12.2 서버 통합 테스트

- `operations/[workDate]` 컨텍스트가 실제 저장과 조회에 반영되는지
- 다른 날짜의 attendance/assignment가 섞이지 않는지
- 인력 조회 화면이 날짜 기준 상태를 올바르게 계산하는지

### 12.3 UI 테스트

- 날짜 선택 화면 렌더링
- 날짜별 운영 화면 헤더와 `날짜 변경` 버튼
- 출근자 목록의 상태별 버튼 노출
- 인력 조회 결과의 상태 기반 액션 버튼

### 12.4 E2E 테스트

핵심 시나리오 1개는 반드시 자동화한다.

1. 날짜 선택
2. 해당 날짜 출근 등록
3. 수동 배정
4. 인력 조회에서 상태 확인
5. 같은 날짜 엑셀 업로드
6. 수동 배정이 엑셀 값으로 덮어써졌는지 확인

## 13. 구현 우선순위

이번 보강 구현은 아래 순서로 진행하는 것이 적절하다.

1. 날짜 중심 라우팅 구조와 진입 화면 개편
2. 날짜별 출근/배정 화면 구현
3. 수동 배정 서버 로직과 `worker_skills` 보정 로직 구현
4. 인력 조회/상세의 날짜 기반 상태 계산 추가
5. 업로드 덮어쓰기 로직 조정
6. 테스트 보강

## 14. 기존 MVP 설계와의 관계

이 문서는 [2026-05-21-workforce-data-pipeline-mvp-design.md](/Users/hylee/Desktop/workforce-os-system/docs/superpowers/specs/2026-05-21-workforce-data-pipeline-mvp-design.md)의 연장선에 있는 보강 설계다.

특히 아래 항목은 이번 문서 기준으로 해석을 갱신한다.

- `오늘 운영 화면` -> `날짜 선택 화면 + 날짜별 운영 대시보드`
- `오늘 출근 등록 화면` -> `선택 날짜 출근 및 수동 배정 화면`
- `업로드 화면의 날짜 입력` -> `선택 날짜 컨텍스트 중심 흐름`

반면 아래 항목은 그대로 유지한다.

- Supabase Auth 기반 관리자 로그인
- 전화번호 기반 인력 식별
- `assignments`와 `worker_skills`를 일관되게 관리해야 한다는 원칙
- 추천 배정과 운영 모니터링은 여전히 다음 단계 기능이라는 점
